# EDF Viewer

Separate Python API and React frontend. The backend serves EDF/BDF files stored in an Azure Blob Storage container with HTTP byte-range support. The frontend reads only nearby data records, decodes and filters signals in a Web Worker, and renders EEG traces on Canvas. The review interface saves manual annotations as per-recording JSON files on the backend.

## Backend

```bash
cd backend
uv sync
# Local development against the Azurite emulator:
npx -p azurite azurite-blob --location .azurite
export AZURE_STORAGE_CONNECTION_STRING=UseDevelopmentStorage=true
uv run uvicorn backend:app --reload
```

Storage is configured with environment variables:

- `AZURE_STORAGE_CONNECTION_STRING` — account key or SAS connection string (or `UseDevelopmentStorage=true` for Azurite), **or**
- `AZURE_STORAGE_ACCOUNT_URL` (e.g. `https://<account>.blob.core.windows.net`) to authenticate with Microsoft Entra ID via `DefaultAzureCredential` (managed identity, `az login`, …). The identity needs the *Storage Blob Data Contributor* role.
- `AZURE_STORAGE_CONTAINER` — container name, default `recordings`. It is created on startup if missing.

Recordings are top-level `.edf`/`.bdf` blobs; annotation and trend sidecars are blobs beside them with the names described below. Recording revisions are the blob size and ETag (`<size>:<etag>`).

To move existing recordings from the Azure File Share (or any directory), mount or copy the share locally and run `uv run python -m backend.migrate <directory>`. Existing blobs are not overwritten. Annotation and trend sidecars are copied with their revisions rewritten for Blob Storage; sidecars whose `size:mtime` revision no longer matches the source file are skipped unless `--ignore-revision` is passed (use it if your copy did not preserve modification times).

The API runs at `http://127.0.0.1:8000`. `GET /api/recordings` lists files; `GET /api/recordings/{name}/file` supports standard `Range: bytes=...` requests. `GET /api/health` is a health check. Recordings are excluded from Git.

Trend results are checkpointed alongside each recording as `<name>.aeeg.v1.bin` and `<name>.spectral.v1.bin` (very long filenames use a hash of the recording name). `GET /api/recordings/{name}/trends/revision` supplies the recording revision (blob size and ETag); `GET` and `PUT /api/recordings/{name}/trends/{aeeg|spectral}` load/save versioned binary caches. The format is `ETR1`, a little-endian 32-bit JSON header length, UTF-8 metadata (kind, revision, selected pairs, epoch count), then little-endian float32 values. aEEG stores time/lower/upper per pair per epoch; spectral trends store 25 frequency bins each of asymmetry, left rhythm and right rhythm per epoch. Each trend saves its accumulated epochs at roughly 5% or 300-second intervals (whichever comes first), on completion, and when switching recordings. Opening a partial trend restores its existing data and resumes at the next 30-second chunk; the spectral worker recomputes the preceding chunk to restore its rhythm boundary state. A tab or browser that closes abruptly can lose work since the last successful checkpoint; a failed save does not stop computation. Older checkpoints cannot replace newer ones, and stale revisions are recomputed. Uploads are size-limited and atomically replaced. This is a cache, not a backup of the original EDF/BDF.

Annotations are stored beside each recording in `<name>.annotations.v1.json` (or a hashed filename for long recording names). `GET` and `PUT /api/recordings/{name}/annotations` load and save a validated JSON document. Changes are saved in order as you edit; the frontend reloads them when switching recordings or refreshing. JSON writes use an atomic replacement and are tied to the recording blob's size and ETag. The API requires write access to the container for both annotations and trend caches. Concurrent editors use last-write-wins behavior.

## Frontend

The **Spectrogram** button toggles a compact time-aligned view beneath every displayed signal in the main canvas. It shows short-time Fourier power up to 40 Hz (limited by each channel's Nyquist frequency). A separate browser worker reads the current EDF window and computes this from calibrated raw voltage independently of waveform display filters. Colours show approximate log power, not a clinically validated measurement; very short windows and non-voltage channels may have no spectral image.

**Band power** toggles one 56 px-high chart fixed below the scrollable waveforms, above the timeline. For the current window, the spectral worker calculates delta (0.5–4 Hz), theta (4–8 Hz), alpha (8–13 Hz), and beta (13–30 Hz) power from calibrated EEG channels and takes the median across eligible channels at each time position. Insufficiently sampled bands are omitted. The chart uses a relative logarithmic display scale and is for exploration, not clinical interpretation.


In a separate terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the URL printed by Vite. During development, Vite proxies `/api` requests to the backend. For deployment, configure your reverse proxy accordingly. 

Use **Upload EDF/BDF** to process a local file in a browser worker and upload it in sequential chunks. Waveform channels above 256 Hz are low-pass filtered and resampled to 256 Hz before upload; lower-rate channels remain unchanged. EDF+/BDF+ annotations are imported once into the recording's `.annotations.v1.json` sidecar when the upload completes. The assembled EDF/BDF retains the original record duration and channel metadata; the local original is never modified or uploaded. The rectangular upload indicator shows bytes sent and average transfer/processing throughput. The API validates the assembled recording before publishing it in the Blob container; uploading the same name again creates a suffixed copy. Processing uses bounded chunks, not a whole-file browser buffer, and the output limit is 2 GiB. Record durations that cannot represent an integer number of 256 Hz samples, oversized individual records, or incomplete files cannot be converted. Derivative recordings, including subsequent saved trends, exclude content above the new 128 Hz Nyquist limit; keep the original locally if full-rate data are needed. Viewing still uses HTTP byte ranges and browser-side decoding. The API has no authentication; secure it before accepting uploads from untrusted users or exposing recordings publicly. For deployment, proxy `/api/uploads` as well as `/api/recordings`, allow request bodies of at least 4 MiB. Upload chunks are staged as uncommitted blocks on the destination blob and become visible atomically only when the upload completes; abandoned blocks are discarded by Blob Storage after seven days. In-progress upload sessions are held in one API process and do not survive a restart.

EDF+D/BDF+D uploads join data records into a continuous EDF+C/BDF+C timeline. Recording gaps are removed, **not filled with invented samples**: annotation timestamps and the EDF+ annotation channel's TALs are remapped, and the sidecar receives a timestamp marker at each removed gap. This shortens the recording; retain the original for wall-clock timing and review the gap markers when interpreting the converted recording. Files with missing or overlapping record timestamps, or annotation channels too small for rewritten timestamps, fail conversion rather than silently dropping data.

During upload, separate browser workers calculate aEEG and spectral trends from the converted EDF/BDF records using the same algorithms as the later viewer calculation. Completed trends are saved to the backend after the recording is published; if either calculation or save fails, opening the recording can compute the missing trend normally. Cancelled uploads do not save partial trends. Trend processing may extend upload time, but needs no additional recording download.

Waveform filters have separate EEG, ECG and AUX presets and on/off switches; switching types preserves their values. EEG and ECG start enabled, while AUX starts disabled. ECG defaults to a 2 Hz high-pass, 70 Hz low-pass, 50 Hz notch and fourth-order slope when the channel sampling rate permits. Recognized scalp/ear electrode labels and derived montage channels use EEG filters; ECG/EKG labels use ECG filters; other original channels (including EOG, EMG and respiration) use AUX filters. Turning a type off bypasses its filters without changing its presets. The selected type's Nyquist limit determines which filter values can be entered. The spectrum of a selected waveform channel uses that channel's filters; spectrogram, band-power and saved trends remain based on unfiltered samples.

**Analyze** toggles per-window artifact screening. Once the waveform is displayed, the waveform worker transfers a copy of its already-cached raw records to a separate analysis worker, avoiding a second network request. Cached records are kept by the viewer even when Analyze is off; only the visible window is copied when Analyze is enabled. The analysis worker checks unfiltered calibrated EEG for flatlines, unusually large amplitudes, abrupt baseline shifts and sustained high-frequency muscle-like activity. Amplitude checks compare quarter-second peak-to-peak range and excursion from the viewport's median with the lower 30th-percentile windows, using conservative absolute µV floors; muscle checks use sustained high-frequency energy. This is a heuristic adaptation of the peak/flat and high-frequency approaches described in MNE-Python's `annotate_amplitude` and `annotate_muscle_zscore` documentation, **not** their validated implementation or clinical criteria. Dashed black boxes surround the visible waveform excursions, merge when close horizontally or across channels, and stay inside the viewport as it scrolls. They do not obstruct selection, persist as annotations or modify recordings. Results are discarded when the window changes and recalculated for the new view. Large physiological events can also be boxed; review them manually before adding annotations.

The site opens on the Files list without loading a recording. Select a file to open the viewer; the top-bar Files button returns to the list. Filters and navigation appear only while viewing a recording. Navigate with the transport controls or bottom timeline, and change the timebase or zoom. The EDF worker caches source data records for up to three windows before and after the current window. Each channel draws a connected first/min/max/last line (all samples when fewer than one per plot pixel) below nine samples per plot pixel; at nine or more it draws separate min–max vertical strokes to preserve amplitude extremes with fewer drawn segments. The top bar shows the current mode, or Mixed if channels differ. Only the currently visible channels are drawn on the waveform canvas; scrolling redraws the newly visible channels. Labels and the grid are separate layers, so aligned page changes do not redraw them. The viewer handles continuous EDF/EDF+ and BDF data; EDF+ annotation channels are omitted from the waveform view. Discontinuous files must be converted through upload before viewing.

The montage menu includes Original, longitudinal bipolar, transverse bipolar, Cz reference, and Local Laplacian. Local Laplacian subtracts the mean of four or five explicitly defined neighbors from each of nine central electrodes; it is a voltage contrast in µV, **not** a coordinate-based spherical-spline current-source-density estimate. Missing neighbors omit that derivation. Derived signals require matching sample counts, units, and recognized reference suffixes (`-REF`, `-AVG`, or `-LE`); an unlabeled reference is assumed to match other unlabeled channels but cannot be verified from the EDF labels. If several channels share an electrode label, the first is used. The spectrogram and median-across-displayed-EEG-channels band-power plot use the same montage derivations as the waveform, so switching montages changes those plots; auxiliary channels stay raw and are excluded from band power. Full-record trends retain their existing longitudinal derivations and do not depend on the display montage.

Open **Trends** beside Channels and Annotations to view two independent left/right bipolar aEEG-style amplitude bands and click a trend to navigate the raw waveform. Once the first waveform window is drawn, the browser loads any compatible saved trends automatically; missing or partial trends start processing in separate workers using bounded 30-second HTTP-range chunks of the recording's calibrated EDF samples. Viewport requests have high fetch priority: trend reads have low priority, in-flight trend reads are cancelled during viewport loading, and the workers wait for the next viewport paint before continuing. The Trends panel need not be open. It selects C3–P3/C4–P4 (or another available matched pair), bandpasses at 2–15 Hz, rectifies and smooths the result, and retains one-second lower/upper envelope estimates for the entire recording. Zoom, pan, or return to the overview in the Trends panel without recomputing. Closing Trends does not stop processing or discard the results; switching recordings stops processing, while reopening resumes from the latest saved checkpoint. Trend data grow with recording length, rather than keeping raw EEG in memory. Processing is independent of waveform display filters and montage. This is an **exploratory prototype**, not a validated conventional or clinical aEEG implementation; its envelope statistics, filtering, and scale must be validated against a reference before clinical use.

When mirrored left/right bipolar derivations are available, a second background worker computes **full-record spectral trends** across up to eight homologous pairs (frontal, temporal, central, and posterior) from calibrated raw EDF samples; aEEG continues to use its selected left/right pair. Each one-second step uses a four-second Hann-windowed FFT for every available derivation, independently of the viewport spectrogram and band-power display. The worker averages the signed power asymmetry of eligible matched pairs at each frequency, producing an asymmetry heatmap (blue: stronger left; red: stronger right). It also averages spectral peak prominence across pairs on each side, then displays the lower prominence across two consecutive windows in left/right heatmaps. Both displays cover 1–25 Hz where the sampling rates permit; grey cells indicate missing or unavailable values. Per-pair signed asymmetry is `(right power - left power) / (right power + left power)` with a small stabilizer; the rhythm proxy compares each 1 Hz bin to nearby bins. Averaging can hide focal changes, so these are **exploratory displays**, not Persyst-equivalent rhythmicity or seizure detectors; artifacts and normal rhythms may appear prominently. Trend data grow progressively in browser memory while the worker runs, share the aEEG chart's zoom and click-to-seek navigation, and are recalled from the backend after refresh once computation and upload finish.

All zoom levels (from 0.1 to 60 s) render connected lines on a shared plotting canvas, allowing signals to overlap neighboring channel positions without clipping at row boundaries. Close zoom levels draw every sample; when multiple samples occupy a horizontal pixel, the line connects that pixel's first, last, minimum, and maximum samples in chronological order. Every sample is still read when decoding, but wide windows send and draw fewer points without losing their peaks.

The review screen mirrors the compact three-row Avinya toolbar, dense traces and right-hand panel, while retaining this project's HTTP-range and browser-worker pipeline. The default montage is Original; derived channels are computed in the browser and never change the EDF. Scalp traces use electrode-based colors (odd blue, even red, midline dark); ECG is green, EOG purple, EMG amber and respiratory signals teal. Auxiliary channels retain their original data rather than being subtracted as EEG pairs. The toolbars provide montage presets, channel selection, high-pass and low-pass filters, a 50/60 Hz notch, editable sensitivity (µV per division), editable channel spacing (24–400 px per row, without changing signal amplitude), per-window centering, polarity inversion, a sticky seconds axis and major/minor time subdivisions (0.2 seconds at a 10-second timebase), plus horizontal amplitude divisions. Click a waveform for a timestamp annotation or drag across it to highlight a time segment. Type a label and press Enter to save, or press Escape to cancel; navigating or changing the timebase also cancels an unsaved annotation. Click a label to select it and reveal its remove button. The Annotations panel lists saved items and lets you hide or show them on the waveform. Annotations are saved to the backend as JSON and reloaded when reopening the recording; annotations created in the viewer are **not** written into the EDF itself. Uploaded EDF+ annotation channels are imported into this list once. Server-side analysis remains unavailable.

Filtering uses bidirectional second-order sections with reflected endpoints and extra EDF data around the window. Filters apply to EEG and auxiliary channels alike; a channel is left raw when any enabled cutoff is at or above its Nyquist frequency. Frequency choices must be below at least one visible channel's Nyquist limit. The **Slope** control selects Standard (2nd-order Butterworth, one biquad per high/low-pass edge) or Steep (4th-order Butterworth, two different-Q biquads per edge). Each section is applied forward and backward, making the effective magnitude roll-off steeper and approximately zero phase, with possible edge effects; the notch remains one Q=30 section in either mode. Switching filters reprocesses cached raw samples; it never alters the file. Bipolar pairs require matching sample rates and units. Sensitivity applies in µV/div to every voltage channel (V, mV, µV/uV), including ECG, EOG and EMG. Channels with non-voltage units use an auto-scaled baseline at 200 µV/div and scale proportionally when sensitivity changes; their labels show the relative multiplier rather than misrepresenting a physical voltage. Filters, montages and per-window centering are intended for exploration, **not clinical interpretation**.

The default view uses all channels in Original montage, LFF 1 Hz, HFF 70 Hz, notch 50 Hz, Steep (4th-order) slope, sensitivity 50 µV/div, channel spacing 24 px, and a 10-second timebase. Annotations start closed. If no channel has a Nyquist frequency above a default filter cutoff, that filter starts Off.

In the Annotations panel, **Show all** and **Show none** control viewport overlays; each row also has its own Show/Hide control. The bottom timeline always shows every saved annotation across the full recording, as a line for a timestamp or a shaded block for a segment, regardless of viewport visibility.
Click a saved annotation's name in the panel or on the waveform to rename it. Press Enter or click away to save; press Escape to cancel. Empty names are not saved.

Filter frequencies, sensitivity, channel spacing, and timebase share editable preset fields: select a suggestion or type a value and press **Enter**. Custom filter frequencies must be at least 0.05 Hz and strictly below the selected channels' highest Nyquist frequency; LFF must also remain below HFF. Channel spacing accepts whole numbers from 24 to 400 px. Values are validated before applying; set individual filters to Off to disable them without modifying the recording. The ± controls beside each channel adjust that channel's sensitivity by 5 µV/div without changing other channels or the global setting. Adjustments persist while paging and switching montages, and reset when switching recordings or resetting the display.

Use **←/→** to step back or forward by half a page, **↑/↓** to scroll one channel row, and the mouse wheel to scroll through channels normally. Zoom using the toolbar buttons or timebase field. Arrow shortcuts do not intercept input fields; scrollbars are hidden to leave more room for signals.
